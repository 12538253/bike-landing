# 실제 블로그 사례 카드 이미지

## 목표

실제 매입 사례 카드 세 장이 모두 같은 기존 이미지를 보여주는 문제를 고친다. 각 카드에는 해당 공식 블로그 글에 게시된 실제 바이크 사진을 사용해 차종과 사례가 바로 구분되게 한다.

## 확정한 구성

- ADV350: 서울 은평구 공식 글 `224355424035`의 대표 차량 사진
- PCX125: 인천 부평 공식 글 `224362894515`의 대표 차량 사진
- 아이언883: 부천 공식 글 `224351926598`의 대표 차량 사진
- 노출 순서는 `ADV350 → PCX125 → 아이언883`으로 유지한다.
- 사용자가 실제 블로그 사진 사용을 명시적으로 요청했으므로, 사진 안에 포함된 바이크매니저 전화번호·홍보 문구는 원본의 일부로 유지한다.

## 자산 처리

- 네이버 CDN을 운영 화면에서 직접 호출하지 않는다.
- 공개된 사진을 로컬 WebP로 변환해 `public/images/cases/`에 저장한다.
- 파일명은 `adv350.webp`, `pcx125.webp`, `iron883.webp`로 고정한다.
- 각 파일은 800×600 기준으로 만들고 180KB 이하를 유지한다.
- 얼굴·번호판이 보이지 않고 차종이 식별되는 사진을 우선한다.
- 사진 자체를 생성하거나 차량 형태를 수정하지 않는다.

## 카드 표현

- 기존 카드 높이, 지역·차종·요약, 원문 링크와 호버 확대 동작을 유지한다.
- 카드별 `object-position`만 조정해 세로형 카드에서도 차량의 핵심 형태가 잘리지 않게 한다.
- 어두운 그라데이션은 카드 하단 문구를 읽을 수 있는 수준으로 유지하되, 실제 차량 색상이 지나치게 죽지 않도록 이미지 필터를 소폭 완화한다.
- 기존의 “기존 사이트 자산” 안내는 실제 공식 블로그 사진을 사용한다는 사실형 문구로 바꾼다.

## 검증

- 정적 export에서 세 카드가 서로 다른 로컬 WebP를 사용한다.
- 세 이미지가 모두 로드되고 자연 크기가 0보다 크다.
- 320·390·768·1440px에서 카드 이미지와 문구가 겹쳐 읽기 어려운 문제가 없다.
- 외부 이미지 URL이나 네이버 CDN 핫링크가 빌드 결과에 남지 않는다.
- lint, build, 정적 테스트, Chromium 테스트와 npm audit를 통과한다.
- 작업 브랜치 미리보기만 갱신하며 `main`과 운영 설정은 변경하지 않는다.
