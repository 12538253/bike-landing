# 두 갈래 거래 경로 시그니처 디자인

## 목적

BMW Motorrad의 화면을 복제하지 않고, 큰 실제 사진·어두운 프레임·짧은 정보 계층·제자리 확장이라는 원리만 바이크매니저의 현장 거래 방식에 맞게 재해석한다. 기존 `TradeMethodComparison` 하나를 교체하며 중복 비교 섹션은 만들지 않는다.

이 구간이 페이지의 유일한 시그니처 인터랙션이 된다. 이후 사용자 카피 감량 결정에 따라 `ProcessStory`는 중복 절차로 판단해 페이지에서 제거한다. 최신 정보 구조는 `2026-08-15-landing-copy-budget-design.md`가 우선한다.

## 정보 구조와 문구

섹션 제목:

> 차량은 곁에 두고, 거래 조건은 현장에서 확인하세요.

도입문:

> 차량이 내 손을 떠나는 시점에 따라 확인해야 할 조건이 달라집니다. 바이크매니저는 약속한 장소로 직접 방문해 차량 상태와 최종 금액을 함께 확인합니다.

DOM과 시각 순서는 항상 다음과 같다.

1. `바이크매니저 직접 방문`
   - `방문 일정 조율 → 현장에서 함께 검수 → 최종 금액 확인 → 입금 확인 → 상차`
   - `바이크매니저는 약속한 장소에서 차량을 함께 확인하고, 최종 금액과 계약 내용을 안내한 뒤 입금 확인 후 상차합니다.`
   - 확인 카드: `입금 확인` / `확인 후 상차`
   - CTA: `사진 보내고 방문 일정 확인`
2. `차량을 먼저 보내는 방식`
   - `출발 전 최종 금액과 감가 기준 확인 → 금액 변경 시 반환 조건 확인 → 왕복 운임 부담 확인`
   - `차량을 먼저 보내는 거래라면 출발 전에 최종 금액, 감가 기준, 반환 조건과 운임 부담을 확인하세요.`

공포·경쟁사 일반화·절대 표현·금액 보장은 추가하지 않는다.

## 시각 언어

- 배경은 딥 페트롤 `#0C1A1C`, 본문은 웜 아이보리, 직접 방문 경로는 브라스·코퍼, 먼저 보내는 경로는 스틸·중성 회색을 쓴다.
- 헤딩과 카드 사이에 BM의 우상향 화살표에서 가져온 갈라지는 경로 SVG를 둔다. BMW의 파랑, 삼각 탭, 카드 비율, 폰트와 전환 타이밍은 모사하지 않는다.
- 경로 선은 장식 요소이므로 항상 `aria-hidden`이다. 모션 허용 환경에서 섹션에 처음 진입할 때 한 번만 그려진다.
- 실제 공식 블로그 사진을 크게 쓴다. 직접 방문은 ADV350의 늦은 시간 상차 장면, 먼저 보내는 방식은 PCX125 측면 사진을 별도 로컬 WebP로 최적화한다. 두 이미지는 설명을 보조하는 실제 차량 사진이며 경쟁 거래의 실제 사례라고 주장하지 않는다.
- 승인 사진 안의 업체명·대표 전화 문구는 원본의 일부로 유지한다. 얼굴·읽히는 번호판은 없는 컷만 사용한다.

## 컴포넌트와 상태

`TradeMethodComparison`은 서버 섹션으로 남고, 작은 클라이언트 자식 `TransactionPaths`가 상호작용만 담당한다.

콘텐츠는 `content/site.ts`의 키 기반 객체 `tradePaths.directVisit`와 `tradePaths.sendFirst`에 둔다. 배열 순서나 CSS 인덱스에 의미를 결합하지 않는다. 카카오 URL은 하나의 상수에서 재사용하고 CTA 식별자 `method-kakao`를 추가한다.

클라이언트 상태:

- `enhanced`: `min-width: 960px`, fine pointer, hover 가능, 모션 감소 아님일 때만 참
- `pinnedPath`: 클릭·Enter·Space로 고정한 경로, 기본은 직접 방문
- `previewPath`: hover 중 임시 경로
- `focusedPath`: 카드 내부 키보드 포커스 경로이며 hover보다 우선
- `revealed`: 경로 SVG가 처음 뷰포트에 들어왔는지 여부

활성 경로는 `focusedPath ?? previewPath ?? pinnedPath`로 결정한다. pointer leave와 카드 focus out은 고정 경로로 복귀한다.

각 경로는 `<article>` 안에 네이티브 `<button aria-expanded aria-controls>`와 별도 상세 패널을 둔다. CTA는 버튼 안에 중첩하지 않고 상세 패널의 실제 `<a>`로 둔다. 향상되지 않은 환경에서는 두 상세 패널을 모두 노출한다.

## 동작

- 데스크톱 향상 상태의 기본 활성 경로는 직접 방문이다.
- hover/focus 시 해당 카드가 임시 활성화된다.
- click·Enter·Space 시 해당 카드가 고정된다.
- 활성/비활성 폭은 약 `1.12fr / 0.88fr`; 두 패널을 normal flow에 남겨 가장 큰 intrinsic height를 공유하고 다음 섹션이 움직이지 않게 한다. literal pixel height는 사용하지 않는다.
- 활성 사진은 최대 `scale(1.03)`만 적용한다. 상세 패널은 `opacity`와 작은 `translate`로 나타난다.
- 스크롤 제어, 자동 캐러셀, GSAP, WebGL, 3D 효과는 추가하지 않는다.

## 반응형·폴백

- `>=960px` + fine pointer + motion 허용: 선택·확장 인터랙션
- `761–959px`: 직접 방문 우선의 두 정적 카드
- `<=760px`: 직접 방문 → 먼저 보내는 방식의 한 열 정적 카드
- 모든 버튼·CTA의 유효 터치 영역은 44px 이상
- `prefers-reduced-motion: reduce`: 선 그리기·확장·사진 확대 없이 두 상세 패널을 정적으로 노출
- JavaScript 비활성: 서버 HTML에서 두 상세 패널과 경로 선을 모두 표시

## 실제 사례 레이아웃

필터는 추가하지 않는다. 사례가 세 건뿐인 현재는 `큰 대표 사례 1 + 세로 사례 2`가 더 명확하다.

- ADV350은 `featured`, PCX125·아이언883은 `portrait` 메타데이터를 갖는다.
- `>=1120px`: 약 `1.6fr 0.8fr 0.8fr`
- `761–1119px`: ADV350이 왼쪽 두 행을 차지하고 오른쪽에 두 세로 카드가 쌓인다.
- `<=760px`: ADV350 → PCX125 → 아이언883 한 열

모든 카드는 기존 공식 블로그 링크·키보드 접근·hover 1.03배·모바일 전체 설명 표시를 유지한다.

## 거래 4단계

초기 구현에서는 짧은 정적 레일로 축소했으나, 사용자 검토에서 TransactionPaths와 같은 절차를 반복한다고 판단했다. 최종 버전에서는 `ProcessStory`와 별도 4단계 섹션을 제거한다. 문의 준비는 QuoteChecklist, 현장 거래 순서는 TransactionPaths가 맡는다.

## 검증 기준

- 정확한 제목·설명·두 경로 문구가 한 번씩 출력되고 직접 방문이 DOM에서 먼저 온다.
- 데스크톱 hover/focus/click 고정과 복귀 규칙이 동작한다.
- 경로 선은 진입 때 한 번만 나타나고 reduced-motion/JS-off에서는 정적으로 보인다.
- 모바일·reduced-motion·JS-off에서 두 경로의 핵심 정보가 모두 보인다.
- 320·390·768·960·1440px에서 가로 넘침, 포커스 순서 역전, CTA 겹침, 다음 섹션 레이아웃 이동이 없다.
- 사례 카드가 desktop/tablet/mobile에서 승인된 비대칭·단일열 배치를 따른다.
- 새 런타임 코드는 페이지 전용 gzip 35KB 예산 안에 남는다.
- 로컬 WebP만 쓰며 새 이미지도 800px 최장변, 180KB 미만을 지킨다.
