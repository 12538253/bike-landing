# 한글 줄바꿈과 README 정리

## 목표

페이지 문구의 뜻은 그대로 두고 제목이 문장 중간에서 어색하게 섞이는 문제를 고친다. README는 소개 문구를 줄이고 실제 수정·검증·배포에 필요한 내용만 남긴다.

## 확인한 원인

- 히어로 제목은 폭이 `720px`로 제한돼 있지만 글자 크기는 최대 `80px`까지 커진다.
- `text-wrap: balance`가 줄 길이만 맞추면서 `됩니다. 직접 찾아가`처럼 서로 다른 문장을 한 줄에 배치한다.
- 공통 섹션 제목도 폭은 고정된 채 글자 크기만 화면에 따라 커져, 1200px보다 1440px에서 줄 수가 늘어나는 경우가 있다.

## 설계

- 히어로 제목은 두 문장을 각각 의미 단위로 렌더링한다. 넓은 화면에서는 두 줄로 보이고, 작은 화면에서는 각 문장 안에서만 다시 줄이 바뀐다.
- 히어로 제목의 최대 크기를 `3.5rem`으로 낮추고 가용 폭을 `58rem`까지 넓힌다. 운영체제별 한글 글꼴 폭 차이에도 두 문장 구조가 유지되도록 하면서 사진과 CTA의 시각적 우선순위는 보존한다.
- 공통 섹션 제목은 최대 글자 크기와 측정 폭을 함께 조정해 큰 화면에서 불필요하게 줄 수가 늘지 않게 한다.
- 본문과 설명에는 `text-wrap: pretty`를 적용해 짧은 마지막 줄을 줄인다. 기존 `word-break: keep-all`은 유지한다.
- 320·390·768·960·1200·1440px에서 제목, 버튼, 가로 넘침을 확인한다.
- README는 저장소 역할, 실행 명령, 자주 수정하는 파일, 검증, 배포 주의사항, 사진·로고 확인 사항 순서로 작성한다. 사이트 홍보 문구와 구현 자랑은 넣지 않는다.

## 변경하지 않는 것

- 전화번호, 주소, URL, 수치, 사례와 거래 절차의 뜻
- 색상, 사진, CTA 동작, 섹션 순서
- `main`, 운영 도메인, Cloudflare DNS
- 새로운 패키지나 외부 서비스

## 추가로 반영한 사례 구성

- 공식 블로그에서 확인되는 최근 사례 흐름에 맞춰 `ADV350 → PCX125 → 아이언883` 순서로 배치한다.
- PCX125는 확인 가능한 최신 인천 부평 글로 연결한다.
- 공개된 ADV350·XMAX300·R6·베스파·포르자·PCX 대표 사진은 중앙에 큰 홍보 문구가 합성돼 있어 이번 미리보기 자산으로 쓰지 않는다.
- 사례별 깨끗한 원본을 확보하면 번호판·얼굴·자택 단서를 확인하고 로컬 WebP로 교체한다.

## 검증 기준

- 1440px 히어로 제목은 두 문장 단위의 두 줄로 보인다.
- 모바일에서 첫 문장 끝과 둘째 문장 시작이 한 줄에 섞이지 않는다.
- 주요 중앙 정렬 섹션 제목은 1440px에서 불필요한 추가 줄이 생기지 않는다.
- 기존 Playwright, 정적 테스트, lint, build가 모두 통과한다.
- README의 명령, URL, 버전, 배포 사실은 기존 문서와 일치한다.
