# 랜딩페이지 카피 예산과 10초 정보 구조

## 목적

홈페이지는 블로그 내용을 다시 설명하는 문서가 아니라, 처음 온 판매자가 10초 안에 업체의 역할과 거래 원칙을 이해하고 카카오톡이나 전화로 문의하도록 돕는 랜딩페이지다. 실제 사진과 짧은 거래 경로가 신뢰를 만들고, 상세 조건은 접힌 안내와 공식 블로그로 보낸다.

현재 390×844 화면은 약 15.03개 뷰포트, 기본 노출 문구는 약 2,249자다. 최종 목표는 기본 노출 문구를 30~40% 줄이고 모바일 길이를 약 9~10개 뷰포트로 줄이는 것이다.

## 반드시 남길 정보

- 인천·서울·경기 방문 매입
- 생활형 스쿠터부터 대형 바이크까지 상담 가능한 범위
- 사진을 보내면 예상 견적과 방문 시간을 먼저 안내한다는 점
- 현장 확인 → 최종 금액 확인 → 입금 확인 후 상차
- 공식 블로그의 실제 매입 사진과 사례
- 대표 전화와 카카오톡 문의
- 사진 견적은 예상 금액이고 현장 상태에 따라 달라질 수 있다는 점
- 24시간은 문의 접수이며 즉시 방문 보장이 아니라는 점
- 명의·등록·서류 상태에 따라 추가 확인이 필요하다는 점
- 개인 거래가 가격 면에서 더 유리할 수 있다는 솔직한 안내

## 최종 정보 구조

1. Hero
2. 제목만 남긴 compact TrustBar
3. TransactionPaths (`id="process"`)
4. CaseStudies와 공식 블로그·네이버 플레이스 링크
5. QuoteChecklist
6. 축약 PurchaseGuide
7. FAQ 3개
8. LocationFinal

다음 독립 섹션은 제거한다.

- `ProcessSection` / `ProcessStory`: TransactionPaths와 내용이 겹친다.
- `HonestComparison`: 고유한 한 문장만 TransactionPaths 아래에 남긴다.
- `NaverProof`: 블로그 링크는 CaseStudies, 플레이스 링크는 CaseStudies와 LocationFinal로 옮긴다.

헤더의 `#process` 링크는 TransactionPaths로 연결한다. 메타데이터와 LocalBusiness JSON-LD는 바꾸지 않는다.

## 노출 카피

### Hero

- 설명: `사진으로 예상 견적과 방문 시간을 먼저 안내합니다. 현장에서 차량 상태와 최종 금액을 확인하고, 판매대금 입금 확인 후 상차합니다.`
- 주의문: `사진 견적은 예상 금액이며, 최종 금액은 현장 상태에 따라 달라질 수 있습니다.`

### TrustBar

- `경력 10년 이상`
- `24시간 문의 접수`
- `직접 방문·현장 확인`
- `입금 확인 후 상차`

설명 문장은 표시하지 않는다. 모바일도 2×2 compact grid로 유지한다.

### TransactionPaths

- 기존 제목을 유지한다.
- 도입: `약속한 장소에서 차량 상태와 최종 금액을 함께 확인합니다.`
- 직접 방문 단계: `방문 일정 → 현장 확인 → 최종 금액 → 입금 확인 → 상차`
- 직접 방문 상세: `약속한 장소에서 차량을 함께 확인하고, 최종 금액 안내와 입금 확인을 마친 뒤 상차합니다.`
- 먼저 보내는 단계: `최종 금액·감가 기준 → 반환 조건 → 왕복 운임`
- 먼저 보내는 상세: `차량을 먼저 보낸다면 출발 전에 최종 금액, 감가 기준, 반환 조건과 왕복 운임을 확인하세요.`
- 하단 메모: `개인 거래는 가격 면에서 더 유리할 수 있습니다. 업체 매입은 시간과 절차를 줄이는 방식입니다.`

기본 카드에는 제목과 짧은 경로만 보이고, 향상된 데스크톱에서는 선택한 카드의 상세만 보인다. 정적 폴백에는 두 상세가 모두 남는다.

### CaseStudies

- 제목: `실제 매입 사진과 기록을 확인하세요`
- 소개: `당시 차량 사진과 진행 내용은 각 원문에서 확인할 수 있습니다.`
- 반복되는 `공식 블로그 사례` 배지는 제거한다.
- 링크 문구는 `원문 보기`로 줄인다.
- featured 사례만 한 문장 요약을 유지하고 portrait 사례는 지역·차종·링크만 표시한다.
- 하단에 `공식 블로그에서 더 많은 사례 보기`, `네이버 플레이스·리뷰 보기`를 둔다.

### QuoteChecklist

- 제목: `사진과 8가지 정보만 보내주세요`
- 설명: `밝은 곳에서 전체 모습과 하자 부위를 가까이 찍어주세요.`
- 기존 8개 항목을 유지한다.
- 모바일은 2×4 compact grid로 줄인다.

### PurchaseGuide

- 제목: `스쿠터부터 대형 바이크까지 상담합니다`
- 설명: `차량 상태와 등록 정보를 확인한 뒤 매입 가능 여부와 필요한 서류를 안내합니다.`
- native `<details>` 요약: `명의·서류가 다른 경우`
- 상세: `보통 신분증과 이륜자동차 사용신고필증 또는 폐지증명서를 확인합니다. 타인·법인·외국인 명의, 미성년자 소유, 서류 분실, 차대번호 훼손·재타각 차량은 추가 확인이 필요합니다. 확인 결과에 따라 진행이 어렵거나 추가 서류가 필요할 수 있습니다.`

## TransactionPaths 높이

고정 높이는 숫자 `660px`을 뜻하지 않는다. 두 패널을 normal flow에 남겨 가장 큰 고유 높이를 공유하고, inactive 패널은 `visibility`, `opacity`, `inert`, `aria-hidden`, `tabIndex`로 가린다. 하드코딩한 grid/article height는 제거하고 이미지 영역만 clip한다. 이 방식으로 상태 전환 전후 높이를 유지하면서 960px과 1440px에서 CTA 전체 48px가 카드 안에 들어오게 한다.

## 검증 기준

- 기본 노출 문구는 기존 약 2,249자보다 30~40% 적다. 브라우저에서 공백을 제외하고 닫힌 FAQ/detail 답변, `sr-only`, `display:none`, `visibility:hidden`, `[aria-hidden=true]`를 제외해 측정한다.
- `ProcessStory`, `HonestComparison`, 독립 `NaverProof`가 DOM에 없다.
- FAQ `<details>`는 정확히 3개이고 PurchaseGuide 상세 `<details>`는 별도로 1개다.
- `#process`는 TransactionPaths 제목을 고정 헤더 아래로 정확히 이동시킨다.
- 390×844 첫 화면에서 업체·지역, 직접 방문, 사진 문의, 현장 금액, 입금 후 상차, 카카오/전화 CTA를 파악할 수 있다.
- 320·390·768·960·1440px에서 가로 넘침이 없다.
- 960·1440px에서 직접 방문 CTA의 전체 사각형이 article과 모든 clipping ancestor 안에 있고 유효 높이가 44px 이상이다.
- 경로 상태 전환 전후 grid 높이 차이는 1px 이하이며 다음 섹션과 겹치지 않는다.
- 200% 글자 크기에서도 CTA가 잘리지 않는다.
- JS-off와 reduced-motion에서 두 경로의 핵심 정보가 모두 보인다.
